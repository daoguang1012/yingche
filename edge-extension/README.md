# 映澈 Edge 扩展 0.6.0

换脸、AI 补帧收为默认关闭的实验功能。首次升级完整备份旧配置到 configBefore060，再关闭两项开关；其余参数与 VSR 选择保留。果冻变形和换脸失跟仍可能发生，本轮没有改动 VSR 链路，也没有新增可靠切镜「保守模式」。桌面端的新稳定美颜与单片设置不等于网页端已改动。

## 更新

1. 打开映澈播放器，并在「换脸」页启用 Edge 连接。0.6.0 播放器保留 0.4.1 桥接协议。
2. 打开 `edge://extensions`，重新加载「映澈」，确认扩展版本 **0.6.0**。
3. 刷新视频网页，再点击扩展「启用当前视频」。补帧和换脸均默认关闭，选择源照片也不会自动开启换脸。

已安装位置：`edge-extension`。固定扩展 ID 和已有参数保留。
如果弹窗提示后台还是旧版，点击「重新加载扩展」后重新打开弹窗，再刷新视频网页。

首次安装：完整解压 ZIP，在 Edge 扩展管理启用开发人员模式，加载其中包含 `manifest.json` 的 `edge-extension` 文件夹。

## 帧率怎么看

- **输入**：浏览器实际交付给扩展的画面数量，每秒计算；倍速、遮挡和浏览器调度可能影响它。
- **输出**：VSR 模式下根据输出视频的实际呈现回调计算。普通画布模式下表示绘制提交频率。
- **生成**：AI 实际生成的中间帧数量。原始帧、重复帧、静止画面和被识别为切镜的帧不计入。

输入已接近 60 FPS 时自动跳过补帧。暂停、拖动进度、切换视频、调整倍速或返回标签页时清空旧帧。
关闭补帧可继续使用原有美颜、换脸和 VSR。缺少 WebGPU、GPU 出错或连续处理超时会回退到普通增强输出；关闭再打开补帧可以重试。

## 历史 0.5.0 数据与当前边界

以下是此前 0.5.0 在隔离 Chromium 153 的样本测量，仅保留为历史记录；它不能证明真实高运动效果合格或本轮日常 Edge 的 VSR 已激活。0.6.0 新测了配置迁移、默认关闭和主动开启后的保存，未重测下列组合：

- 720p / 30 FPS：美颜 + VSR 输出约 **60.1 FPS**；加照片换脸后约 **59.9 FPS**。
- 1080p / 24 FPS：保持 1920×1080 输出，美颜 + VSR 约 **59.9 FPS**。
- 720p / 60 FPS：自动跳过 AI 补帧，实际输出约 **59.7 FPS**。
- 已验证暂停、进度跳转、倍速、画布/视频切换、切镜避让、异常回退和停止后的资源释放。
- 逐帧读取输出视频确认产生新增画面；不是只提高渲染计数。

补帧新增缓冲约 **41 ms（30 FPS）/ 50 ms（24 FPS）**，另有原有 VSR 输出链的延迟。声音继续由原网页播放，不会复制或修改声音。对音画同步非常敏感时可关闭补帧。

快速运动、遮挡、字幕边缘可能出现变形或重影；切镜检测属于启发式处理，无法覆盖所有剪辑。高分辨率和显卡繁忙时不保证达到 60 FPS，屏幕刷新率也会限制输出。
已观察到补帧输出调用 Chromium 的 NVIDIA VSR 路径；是否真正激活超分仍以 NVIDIA App 为准。
日常 Edge 和每一个视频网站没有逐站验收。跨域限制、DRM、跨域 iframe 等边界沿用旧版；兼容捕获依然需要用户在浏览器中选择当前标签页。

## 本地运行与许可

模型随扩展打包，运行时不下载模型，不上传视频。只有原有美颜/换脸分析与本机 `127.0.0.1:18766` 通信。

补帧采用 [Framegen 1.4.0](https://github.com/MONZikWasTaken/Framegen) WebGPU 运行库和 v7-small 权重。代码为 MIT；权重限个人及非商业研究用途，可带原许可原样再分发。许可和来源保存在 `vendor/framegen/`。
